# 4 MB Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every build is a 4 MB MBC3 ("MBC30") ROM that runs on Virtual Console through the MBC30 patch.

**Architecture:** `layout.link` pins the `"Title"` section (`main.asm:567`, `engine/movie/title.asm`) to `ROMX $FF`. `rgbfix -p` then pads the ROM to 4 MB and sets the header's ROM size byte. `tools/bankends.c` counts 256 banks so the build's own bank check accepts `$80`–`$FF` and still stops above `$FF`.

**Tech Stack:** RGBDS 1.0.4 (`make vc`), C (`tools/bankends.c`), Python 3, Azahar via `vc/build_cia.sh`, `vc/gen_ctm.py` and `vc/playtest.py`.

**Spec:** `docs/superpowers/specs/2026-11-15-german-translation-design.md` (section "PR 1: 4 MB build")

## Global Constraints

- Nothing may sit above bank `$FF`.
- `make vc` still produces the VC patch, with no new warnings.
- Labels referenced by `vc.patch.template` keep their names.
- Work happens on branch `4mb-build`, which reaches `master` through a squash-merged PR titled "Build a 4 MB ROM". Commits end with the `Claude-Session:` trailer.
- `$SCRATCH` is a scratch directory outside the repo.

## Review Focus

1. **Bank bytes at `$80` and above:** any code that masks, sign-tests or doubles a bank number breaks once content lands above `$7F`. `Bankswitch` (`home/header.asm:18`) writes the full byte; Task 1 Step 6 greps the remaining `rROMB` writes and bank arithmetic.
2. **Text in a high bank:** later PRs will put text sections above `$7F` (`text_far`, Huffman-compressed text, map scripts). The title screen exercises only code and graphics. Task 2's Azahar run reaches Elm's text, which shows banks below `$80` still work; it doesn't prove text above `$7F`. That proof comes with the first text PR whose sections land there.
3. **The VC helper ROM:** `polishedcrystal-3.2.3_vc.gbc` uses the same `layout.link`. Task 1's check runs on both ROMs.
4. **VC patch hook addresses:** pinning one section can re-pack floating sections and move hooked labels. The patch is generated from `.sym`, and the build's `vc_assert`s check the hooks; Task 2 boots the result.
5. **Above `$FF`:** `tools/bankends` must still stop the build. Task 1 Step 5 checks its guard with a section pinned to `$100`.

```python
rom = open(rom_path, "rb").read()
assert len(rom) == 4 * 1024 * 1024
assert rom[0x147] == 0x10          # MBC3+TIMER+RAM+BATTERY
assert rom[0x148] == 0x07          # 4 MiB, 256 banks
assert header_checksum_ok(rom) and global_checksum_ok(rom)
assert sym_bank(sym_path, "_TitleScreen") == 0xFF

```

Run it on the base ROM. Expected: FAIL on the size assertion (2,097,152 bytes).

- [ ] **Step 5: Check the `$FF` limit**

Expected: `bank_ends.txt` reads `Free space: …/4194304` and lists banks `$00`–`$ff`, with `$ff` partly used.
